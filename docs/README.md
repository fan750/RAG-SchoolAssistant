# 文档目录

文档随仓库版本管理，每份规约、每张图单独一个 PR，评审通过后合并。目录结构按 [README](../README.md) §13。

| 目录 | 内容 | 课程检查点 |
| --- | --- | --- |
| `01-调研报告/` | 调研计划、访谈纪要、调研报告、用户故事清单 | 第 9、10 周 |
| `02-SRS/` | 需求规格说明书、用例图、追溯矩阵 | 第 11 周 |
| `03-需求分析/` | 需求分析规约、分析模型（类图、状态图、顺序图） | 第 12、13 周 |
| `04-设计规约/` | 概要设计、详细设计、API 契约、ADR | 第 14、15 周 |
| `05-测试/` | 测试计划、测试报告、评测集 | 第 16 周及课后 |
| `06-AI使用报告/` | AI 使用报告、把关记录 | 答辩前 |

## 编号约定

| 前缀 | 含义 | 示例 |
| --- | --- | --- |
| REQ-F | 功能需求，与用例一一对应 | REQ-F11 |
| REQ-N | 非功能需求 | REQ-N02 |
| UC / UNF | 用例 / 非功能用例 | UC-11 / UNF-02 |
| DES | 设计条目，设计阶段建立 | DES-11 |
| TC | 测试用例，测试阶段建立 | TC-011 |
| Q | 待确认事项 | Q-3 |
| R | 技术风险 | R-2 |

追溯关系 REQ → UC → DES → TC，当前状态见 [追溯矩阵-v0.md](02-SRS/追溯矩阵-v0.md)。

## 版本规则

- 草稿在分支上以 PR 评审，文件名带版本号，如 `SRS-v0.1-草稿.md`。
- 评审通过后打 Release 标记 `v1.0`。之后的需求改动走「需求变更申请」Issue + PR，并在文档末尾的变更记录登记。
- 每份文档末尾写 AI 使用声明：工具、用途、人工评审人。课程要求 AI 产出必须声明，未声明按学术不端处理。
